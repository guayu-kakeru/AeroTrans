# AeroTrans Windows 安装器与卸载导出设计

> 日期：2026-04-24
> 状态：已通过对话内方案确认，待用户检查书面 spec
> 范围：Windows 安装版、标准卸载入口、API Key 清理、单词本导出保留

## 1. 目标与范围

### 1.1 目标
- 新增标准 Windows 安装版，生成可安装的 `setup.exe`，而不是只依赖绿色便携版。
- 为安装版提供完整卸载程序，使用户能在开始菜单和 Windows “应用和功能”中正常卸载。
- 卸载时始终删除系统凭据中的 API Key。
- 卸载时提供一个选项，允许用户在删除本地数据库前导出单词本内容并保留为文件。

### 1.2 非目标
- 本轮不做 macOS/Linux 安装器与卸载流程。
- 本轮不做“从导出文件重新导入单词本”的 UI。
- 本轮不把“便携版卸载器”作为独立交付物；便携版继续保留现有自注册能力，但完整卸载体验以安装版为主。

## 2. 现状约束

### 2.1 当前工程现状
- `src-tauri/tauri.conf.json` 里 `bundle.active` 为 `false`，说明当前仍是便携包优先。
- `package.json` 只有 `package:portable` 和 `verify:portable`，尚无安装版构建脚本。
- 应用启动时会通过 `src-tauri/src/desktop_registration.rs` 自动写入：
  - `HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\AeroTrans.exe`
  - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\AeroTrans.lnk`
- API Key 通过 `src-tauri/src/security/credential_store.rs` 走系统凭据存储，不在 SQLite 中明文保存。
- 单词本保存在 `aerotrans.sqlite` 的 `vocabulary` 表，当前稳定字段包含：
  - `id`
  - `term`
  - `translation`
  - `context_text`
  - `starred`
  - `ai_memory`
  - `created_at`

### 2.2 设计约束
- 必须兼容现有便携版和当前用户数据目录，不破坏已存在的 SQLite 数据。
- 必须避免与现有“启动时自注册”逻辑冲突，安装版与便携版的注册职责要明确。
- 卸载逻辑必须能在无 API Key、无单词本、数据库损坏、导出目录不存在等情况下安全完成。

## 3. 方案选择

### 3.1 方案 A：继续只有便携版，额外写一个独立卸载器
- 优点：不改变当前分发模型。
- 缺点：用户体验不标准，系统“应用和功能”里没有正式安装项；删除正在运行的绿色程序也更麻烦。

### 3.2 方案 B：切到 Tauri `NSIS` 安装版，标准卸载作为主路径
- 优点：最符合 Windows 用户预期；有标准卸载入口；便于清理注册表、开始菜单、安装目录。
- 缺点：需要补安装器脚本、卸载流程和验证链路。

### 3.3 方案 C：同时做安装版和独立便携卸载器
- 优点：覆盖最全。
- 缺点：实现和维护成本最高，超出本轮必要范围。

### 3.4 结论
- 采用方案 B。
- 继续保留便携包作为高级/免安装使用场景，但“完整卸载”只对安装版承诺标准体验。

## 4. 安装与卸载设计

### 4.1 安装版交付
- 启用 Tauri Windows bundle，目标使用 `nsis`。
- 新增安装版打包脚本，生成 `AeroTrans-setup.exe` 一类的标准安装器产物。
- 安装后需要具备：
  - 开始菜单应用入口
  - Windows 应用列表中的卸载入口
  - 卸载程序文件

### 4.2 与现有自注册逻辑的关系
- 安装版已经由安装器负责注册开始菜单和卸载入口，因此应用运行时的 `desktop_registration` 不应重复写入冲突信息。
- 设计上引入“安装版上下文识别”：
  - 如果当前是安装版运行环境，跳过或最小化 `ensure_current_user_registration()`。
  - 如果当前是便携版运行环境，保留现有自注册行为。
- 这样可以保证：
  - 便携版仍可被 uTools 一类启动器识别。
  - 安装版的注册行为由安装器主导，不出现双重注册和清理不完整。

### 4.3 卸载入口与流程
- 用户从开始菜单、系统设置或控制面板启动卸载程序。
- 卸载程序执行顺序：
  1. 检测主程序是否仍在运行。
  2. 如仍在运行，要求关闭或由安装器处理重启后删除。
  3. 展示卸载选项页。
  4. 根据用户选择决定是否先导出单词本。
  5. 删除 API Key。
  6. 清理本地数据库与应用数据。
  7. 清理安装目录、开始菜单项、卸载注册项。

## 5. 单词本导出保留设计

### 5.1 用户选择
- 卸载选项页提供勾选项：`导出并保留单词本`
- 默认行为：不勾选，执行完整清理。
- 勾选后行为：先导出单词本，再删除本地数据库。

### 5.2 导出格式
- 本轮默认导出为 `JSON`。
- 选择 JSON 的原因：
  - 字段完整，不丢 `aiMemory`、`starred`、`createdAt` 这类结构化信息。
  - 后续若要补“导入单词本”功能，可以直接复用。
- 导出文件结构为对象数组，每项包含：
  - `term`
  - `translation`
  - `contextText`
  - `starred`
  - `aiMemory`
  - `createdAt`

### 5.3 导出路径
- 默认导出到当前用户“文档”目录下：
  - `Documents\AeroTrans Backups\vocabulary-YYYYMMDD-HHMMSS.json`
- 如目录不存在，卸载程序自动创建。
- 如导出失败，卸载程序提示失败原因并允许用户：
  - 返回重试
  - 放弃导出并继续卸载

### 5.4 数据语义
- “保留单词本”在本设计中明确表示：
  - 卸载前导出成文件留档
  - 卸载后不保留原 SQLite 数据库
- 这样能保证卸载后的系统状态干净，不遗留运行数据。

## 6. API Key 与本地数据清理策略

### 6.1 API Key
- 卸载时始终调用现有系统凭据存储删除逻辑。
- 无论用户是否勾选导出单词本，API Key 都必须删除。
- 若凭据本身不存在，卸载继续，不视为失败。

### 6.2 数据库与应用数据
- 未勾选导出：
  - 直接删除应用数据库和相关本地数据目录。
- 勾选导出：
  - 成功导出后再删除应用数据库和相关本地数据目录。
- 若数据库损坏但文件仍可删除：
  - 允许跳过导出并继续清理
  - 若用户勾选导出，则先提示“当前数据库无法完整导出”

### 6.3 注册与快捷方式清理
- 安装版卸载时由安装器清理自身创建的开始菜单项和卸载入口。
- 对已有便携版自注册遗留项，卸载流程额外尝试删除：
  - `App Paths\AeroTrans.exe`
  - `%APPDATA%\Microsoft\Windows\Start Menu\Programs\AeroTrans.lnk`
- 删除失败记录日志，但不阻塞最终卸载完成。

## 7. 组件与职责

### 7.1 Rust 应用层
- 提供稳定的“导出单词本”和“删除 API Key”能力，供安装器脚本或辅助命令调用。
- 复用现有 SQLite 访问和凭据存储实现，避免在安装器脚本里重复解析数据库结构。

### 7.2 安装器脚本层
- 负责安装版注册与标准卸载入口。
- 负责卸载选项 UI、运行中检测、调用导出/清理命令、清理文件与注册信息。

### 7.3 脚本与验证层
- 提供安装版构建命令。
- 提供验证脚本，检查安装产物、卸载产物和导出流程关键文件。

## 8. 错误处理

### 8.1 导出失败
- 给出明确错误信息，例如：
  - 无法打开数据库
  - 无法创建导出目录
  - 无法写入导出文件
- 用户可选择重试或继续卸载。

### 8.2 卸载时程序仍在运行
- 优先提示关闭主程序。
- 如果安装器支持延迟删除或重启后删除，则采用安装器标准能力。

### 8.3 部分清理失败
- API Key 删除失败、快捷方式删除失败、注册表删除失败分别记录到卸载日志。
- 只要主程序和核心数据目录已清理，卸载流程应尽量完成，不因单一残留项完全中断。

## 9. 测试与验收

### 9.1 自动化测试
- 为导出单词本增加 Rust 测试：
  - 正常导出包含预期字段
  - 空单词本导出为空数组
  - AI 联想、星标、时间戳被保留
- 为 API Key 清理增加测试：
  - 有凭据时删除成功
  - 无凭据时返回成功
- 为安装/卸载辅助逻辑增加 Windows 侧测试：
  - 安装版上下文下跳过便携自注册
  - 卸载清理命令包含注册表和开始菜单项

### 9.2 手动验收
- 安装 `setup.exe` 后，系统“应用和功能”里能看到 AeroTrans。
- 开始菜单可启动 AeroTrans。
- 卸载时可见“导出并保留单词本”选项。
- 勾选导出后，`Documents\AeroTrans Backups` 下能看到 JSON 文件，内容字段齐全。
- 卸载完成后：
  - 主程序目录被删除
  - API Key 被删除
  - SQLite 数据被删除
  - 开始菜单入口和卸载入口消失

### 9.3 发布产物
- 保留现有便携版构建。
- 新增安装版构建产物，并把安装版作为面向普通用户的默认推荐下载项。

## 10. 实施边界

### 10.1 本轮会做
- `NSIS` 安装版与标准卸载入口
- 卸载时 API Key 删除
- 卸载时单词本导出保留选项
- 与现有便携自注册逻辑的边界收敛

### 10.2 本轮不做
- JSON 之外的额外导出格式
- 导入单词本功能
- 便携版独立卸载器
- 非 Windows 平台安装器
