# AeroTrans 设计文档（工程化优先）

> 日期：2026-04-08
> 状态：已通过用户评审（对话内确认）
> 优先级顺序：3（工程化）-> 1（MVP主链路）-> 2（学习系统增强）

## 1. 总体架构与阶段划分

### 1.1 目标
- 严格按 `工程化(3) -> MVP主链路(1) -> 学习系统增强(2)` 推进。
- 每一阶段可独立验收，避免一次性交付造成质量失控。

### 1.2 分层架构
1. `src-tauri/`（Rust 宿主层）
- 负责系统托盘、全局快捷键注册与冲突检测、窗口管理（无边框/置顶/透明/鼠标穿透）、SQLite I/O、TTS 桥接。
- 对前端通过 `tauri::command` 暴露稳定接口。

2. `src/`（Vue 3 + Tailwind 前端层）
- 负责 Spotlight 输入框、结果面板、Companion 悬浮窗、设置页、单词本页。
- 负责状态管理（翻译、词库队列、设置）与交互反馈。
- 通过 invoke 与 Rust 层交互。

3. 本地数据层（SQLite）
- 持久化单词记录、来源语境、AI 记忆内容、复习状态、非敏感用户设置。

4. 凭据安全层（OS Credential Store）
- API Key 不进入 SQLite，不以明文形式写入本地数据库或日志。
- 必须调用系统级凭据管理器存储敏感凭据（Windows Credential Manager / macOS Keychain）。
- Tauri 实现使用成熟安全存储方案（如 Keyring/Stronghold 类插件组合），读取时按需解密到内存。

5. AI API 适配层
- 支持 OpenAI 兼容接口配置：`base_url`、`api_key`、`model`。
- 支持低延迟翻译和详情页异步增强两类调用策略。

### 1.3 三阶段里程碑
1. `Phase A（工程化优先）`
- 初始化 Tauri + Vue + Tailwind 骨架。
- 完成 `.gitignore`、分支协作文档、GitHub Actions（对 `dev`/`main` 的 PR 均触发）。
- 建立前后端测试框架并在 CI 跑通。
- 引入数据库 Migration 机制（基于 `PRAGMA user_version` + 增量 SQL 脚本），强制后续 Schema 变更通过迁移脚本执行。

2. `Phase B（MVP 主链路）`
- 实现 Spotlight 极速查词。
- 实现 Companion 智能剪贴板监听刷新（节流 + 格式校验 + 备用热键触发）。
- 实现 SQLite 单词本先落盘再增强。
- 实现快捷键冲突检测与基础设置。

3. `Phase C（学习系统增强）`
- 实现单词详情 AI 异步记忆生成与“重新生成”。
- 实现复习卡片轮播与删除焦点切换。
- 补齐数组边界/循环/删除焦点专项测试。

### 1.4 验收原则
- 每阶段结束均满足“可运行、可测试、可继续迭代”。
- 先稳定性，后体验细化。

## 2. 核心模块设计与数据流

### 2.1 模块划分
1. `Translation Orchestrator`（前端应用服务）
- 接收手动输入、划词复制、快捷键唤起三类输入。
- 正则判定中英方向并路由到翻译策略。
- 输出极速结果或上下文增强结果。

2. `AI Adapter`（前端服务层 + Rust 安全桥接）
- 统一封装 OpenAI 兼容请求。
- 提供 `fastTranslate()` 与 `contextTranslate()`。
- 失败返回结构化错误，便于 UI 分级提示。

3. `Vocabulary Repository`（Rust + SQLite）
- 加词先写本地保证低延迟。
- 字段覆盖词面、释义、语境、星标、复习状态、AI 记忆、时间戳。
- 使用可配置去重/合并策略降低重复数据。

4. `Review Queue Engine`（前端纯逻辑模块）
- 独立管理索引推进、循环、删除焦点迁移。
- 与 UI 解耦，便于高强度单元测试。

5. `Settings Service`
- 管理快捷键与冲突检测缓存。
- 管理透明度、鼠标穿透、TTS、收录策略。
- 管理 API Key 凭据引用，不持久化 API Key 明文；敏感信息统一走 OS 凭据存储。

### 2.2 关键数据流
1. `Spotlight 查询流`
- 唤起 -> 输入 -> 语言判定 -> `fastTranslate()` -> 展示 -> 加词 -> SQLite 落盘。

2. `Companion 沉浸流`
- 开启监听（含智能节流）-> 仅在纯文本且长度符合“单词/短句”特征时读取 -> 悬浮窗刷新 -> 可收藏词条。
- 支持备用触发模式：通过全局快捷键主动读取剪贴板（如双击 `Ctrl`），以规避系统隐私弹窗对沉浸感的影响。

3. `单词详情 AI 增强流`
- 进入详情先读本地 -> 异步生成记忆 -> 回写 SQLite -> 局部刷新。
- 重新生成只覆盖 AI 扩展字段，不改原始词条。

4. `设置变更流`
- 改快捷键 -> 系统冲突校验 -> 冲突阻止保存并提示。
- 无冲突则落盘并立即重新注册。

### 2.3 接口边界
- 前端不直接访问数据库和文件系统。
- Rust 命令层提供稳定 typed DTO。
- 队列核心逻辑禁止散落在 UI 组件内。

## 3. 错误处理与稳定性策略

### 3.1 错误分级
1. 可恢复错误（网络超时、429）
- UI 提示可重试，不覆盖已有结果。

2. 配置错误（Key/URL/Model 异常）
- 设置页即时校验并阻止保存。
- API Key 缺失或凭据读取失败时，阻止发起翻译请求并引导用户修复凭据配置。

3. 系统能力错误（快捷键注册失败、TTS 不可用）
- 明确原因并提供替代建议，避免全局崩溃。

4. 数据一致性错误（SQLite 读写失败）
- 写失败回滚 UI 成功态。
- 读失败进入只读降级，翻译继续可用。

### 3.2 队列稳定性（Off-By-One 重点）
- 所有索引操作统一经 `Review Queue Engine`。
- 固定规则：
  - 下一张：`(index + 1) % length`
  - 上一张：`(index - 1 + length) % length`
  - 删除当前后：
    - 删除最后一项 -> 焦点到新最后一项
    - 删除中间项 -> 焦点到原下一项
    - 删除唯一项 -> 进入空状态
- 操作后不变量检查：
  - `length === 0 => index === -1`
  - `length > 0 => 0 <= index < length`
- 不变量异常时自动修正并记录日志，防白屏。

### 3.3 异步任务隔离
- AI 记忆生成使用后台状态机：`idle -> generating -> success/failed`。
- 详情页切换时取消旧任务或忽略过期回包，防串写。

### 3.4 降级策略
- API 不可用时保留本地词库可读。
- TTS 不可用时仅禁用发音按钮。
- 系统目录不可写时降级到可写目录（优先绿色模式目录）。

### 3.5 可观测性
- 关键链路写本地日志：快捷键、AI 请求、DB 写入、队列跳转。
- 日志脱敏：不记录 API Key 明文，不记录完整敏感文本。

## 4. 测试策略、CI 与交付验收标准

### 4.1 测试分层
1. 单元测试（最高优先级）
- 覆盖队列连续翻页、首尾循环、删除焦点、空/单元素场景。

2. 集成测试
- 覆盖前端 invoke Rust 命令关键链路。

3. 迁移测试
- 覆盖旧版本数据库升级到新版本的迁移过程，验证 `user_version` 与增量 SQL 可重复执行且结果一致。

4. 端到端烟雾测试（后续增强）
- 覆盖应用启动与核心流程可达性。

### 4.2 CI 触发策略（已确认）
- GitHub Actions 触发于：
  - 对 `dev` 的 PR
  - 对 `main` 的 PR
- 必跑项：
  - 前端 lint + test
  - `cargo test`
  - 队列算法专项测试（阻断合并）

### 4.3 打包制品策略
- `main` PR 通过后触发构建任务（探索版）。
- 产物目标：Windows `.exe/.msi`，macOS `.dmg`。
- 首版先保证可构建与可下载，再补签名与发布自动化。

### 4.4 仓库规范
- `.gitignore` 必须排除：
  - `node_modules/`
  - `src-tauri/target/`
  - `.env*`
  - `*.db`、`*.sqlite`
- 分支模型：`main`（稳定发布）、`dev`（集成）、`feature/*`（功能开发，PR 回 `dev`）。

### 4.5 分阶段 Definition of Done
1. Phase A：CI 稳定、目录规范、测试框架可用。
2. Phase B：Spotlight + Companion + SQLite + 快捷键冲突检测可用。
3. Phase C：AI 记忆增强 + 复习系统稳定 + 边界测试全绿。

## 5. 非目标（当前范围外）
- 不在本阶段承诺 OCR、网页划词注入、云同步、多端账号体系。
- 不在首版承诺自动付费计费或模型市场。

## 6. 风险与应对
1. 全局快捷键跨平台行为差异
- 先保证 Windows 稳定，macOS 作为后续平台扩展验证。

2. 第三方模型兼容性差异
- 使用统一适配层并提供请求模板调试入口。

3. 复习队列边界 bug
- 以纯逻辑引擎 + 高强度单测作为第一防线。

4. 剪贴板隐私策略差异（Windows/macOS）
- 使用智能节流 + 格式校验 + 主动触发备用热键，降低系统隐私提示对沉浸体验的影响。

5. Schema 演进导致老版本数据库不兼容
- 通过 `user_version` 与增量迁移脚本确保平滑升级，禁止直接改表绕过迁移。
